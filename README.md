# Voice Remote Bridge

把 Android 电视遥控器的语音键转换为 Windows 语音输入触发动作。

它适合这种场景：遥控器接收端插在 Windows 电脑上，遥控器自带麦克风，但语音键原本只对 Android 电视有效。Voice Remote Bridge 读取指定 USB 接收端的语音键事件，确认遥控器麦克风已经激活，然后切换到目标输入法并触发语音输入。

## 当前交互方式

本项目实测的 `VID_1915/PID_1025` 接收端只发送一次性 Voice Command 脉冲，没有真实的“松手”报告。因此当前推荐交互不是严格的按住说话，而是：

1. 第一次按住遥控器语音键，直到语音图标出现；
2. 松开后正常说话；
3. 说完再次短按语音键，提交文字并关闭语音窗口。

短按第一次语音键不会持续激活遥控器麦克风，所以使用遥控器自身麦克风时，第一次必须长按。

## 已测试环境

| 项目 | 已测试值 |
|---|---|
| 操作系统 | Windows 11 x64 |
| USB 接收端 | `VID_1915&PID_1025` |
| 麦克风端点 | `SG Control Mic` |
| 微信输入法 | WeType `2.1.3.18` |
| 触发快捷键 | `Ctrl+Win+Shift` Toggle |
| 输入场景 | 记事本、Word、ChatGPT，主屏和副屏 |
| 微信客户端 | 开启和退出两种状态均完成实测 |

其他遥控器、接收端、输入法版本和语音软件需要重新学习并实测，不能直接假定兼容。

## 下载与运行

1. 打开 [Releases](https://github.com/sailhu08212/voice-remote-bridge/releases/latest)；
2. 下载 `VoiceRemoteBridge-win-x64.zip`；
3. 解压到固定目录，不要直接在压缩包内运行；
4. 双击 `VoiceRemoteBridge.App.exe`；
5. Windows 如果显示未知发布者提示，请先核对下载来源和文件名。本项目当前没有代码签名证书。

发布包是 Windows x64 自包含版本，普通用户不需要另外安装 .NET。

## 首次配置

### 1. 设备

打开“设备”页：

- “硬件标识”填写接收端的 VID/PID，例如 `VID_1915&PID_1025`；
- “麦克风名称”填写 Windows 中显示的端点名称，例如 `SG Control Mic`；
- 点击“刷新设备”，确认能看到目标 HID 接口；
- 点击“保存基础设置”。

程序只读取指定 VID/PID 的 HID 接口，不采集普通键盘输入。

### 2. 学习语音键

打开“语音键”页：

1. 在“采集通道”中选择目标 Consumer Control/HID 通道；
2. 点击“1. 开始（保持松开）”；
3. 按界面提示完成“现在按住”和“现在松开”；
4. 每一步停留约1秒；
5. 点击“4. 完成学习”。

当前接收端的 `01CF00 → 010000` 是一次性脉冲，约30 ms后的归零不代表实体松手。程序会据此使用“再次按键提交”模式。

### 3. 配置微信输入法适配器

打开“语音软件”页。下面是本机已经实测的推荐值；第三方软件升级后如快捷键变化，应以软件自身设置为准。

| 设置项 | 推荐值 |
|---|---|
| 名称 | `微信输入法（独立）` |
| 触发模型 | `Toggle` |
| 开始快捷键 | `Ctrl+Win+Shift` |
| 注入方式 | `VirtualKey` |
| 必须运行的进程 | `wetype_renderer` |
| 目标输入法 | `WeType` |
| 自动切换输入法 | 开启 |
| 必要时确认启用目标 Profile | 开启 |
| 目标输入法已激活时刷新 TSF 会话 | 开启 |
| 切换后等待 | `300` ms |
| 提交后恢复等待 | `3000` ms |
| 确认语音窗口出现 | 开启 |
| 语音窗口进程 | `wetype_update` |
| 语音窗口类名 | `wetype.flutter.setting` |
| 启动确认最长等待 | `2500` ms |

点击“保存/选择此适配器”。

随后打开微信输入法“设置 → 语音输入 → 快捷键”：

- 保持“启动语音输入”开启，快捷键为 `Ctrl+Win+Shift`；
- **关闭“按住说话”及其 `Ctrl+Win` 快捷键。**

两组快捷键共享 `Ctrl+Win` 前缀。同时开启时，微信输入法内部监听器可能竞争同一组按键事件，表现为主屏/副屏、浏览器或 ChatGPT 偶发无法弹出语音图标。桥接程序不会自动修改微信输入法设置，需要用户手动关闭该项。

程序使用 Windows TSF Profile 精确切换到微信输入法，不模拟 `Ctrl+Shift` 或 `Win+Space`。提交完成后会恢复本轮开始前的输入法。

### 4. 触发与安全

打开“触发与安全”页：

| 设置项 | 当前推荐值 |
|---|---:|
| 交互模式 | 再次按键提交 |
| 长按阈值 | `50` ms |
| 单次最长听写 | `300` 秒 |
| 激活最长等待 | `1200` ms |
| 启动预热忽略时间 | `100` ms |
| RMS 激活阈值 | `0.001` |
| 连续有效音频包数 | `3` |
| 音频交接时间 | `500` ms |

点击“保存参数”，再点击“启动桥接”。顶部状态显示 `Idle` 表示程序正在等待语音键。

以上加速值已在当前 `VID_1915/PID_1025 + SG Control Mic` 组合上完成体验确认。若另一台电脑或同型号遥控器出现偶发首次不弹窗，先把“切换后等待”调到 `500` ms、“启动预热忽略时间”调到 `150` ms；仍不稳定时回退到 `1000` ms、`250` ms、`5` 个连续音频包。

## 日常使用

1. 在目标软件中单击需要输入文字的位置；
2. 第一次长按遥控器语音键；
3. 继续按住，等待语音图标出现；
4. 松开语音键并说话；
5. 说完再次短按语音键；
6. 等待文字提交并恢复原输入法。

在输入法切换和语音窗口确认期间不要切换窗口，否则程序会主动取消本轮，防止文字写入错误位置。

## 主屏和副屏

程序匹配语音窗口的进程名、窗口类和可见状态，不把某个屏幕坐标写死。当前版本已在主屏和副屏的普通输入框及 ChatGPT 中完成实测。

如果某次第三方软件升级后只有特定屏幕失败：

1. 先把光标放到普通记事本中对照测试；
2. 在“诊断”页查看是否完成输入法切换、快捷键发送和语音窗口确认；
3. 不要连续反复按键；等待状态回到 `Idle` 后再测试；
4. 必要时重启目标输入法和目标应用。

## 开机自启动

在“触发与安全”页勾选“登录 Windows 后自动启动（后台进入托盘）”，再保存参数。

该功能只写入当前用户的 Windows 启动项：

- 不安装 Windows 服务；
- 不要求管理员权限；
- 启动后直接进入托盘，不抢当前输入焦点；
- 取消勾选并保存即可关闭。

## 紧急恢复

如果出现状态长时间停在 `Speaking`、输入法未恢复或怀疑组合键异常：

1. 点击窗口底部的“紧急释放按键”；
2. 等待顶部状态回到 `Idle`；
3. 仍未恢复时点击“停止桥接”，然后重新启动桥接；
4. 再运行“诊断”页的“一键自检”。

所有模拟按键在正常停止、异常、退出、设备断开和守护超时时都会尝试成对释放。

## 常见问题

### 长按后没有语音图标

- 确认顶部状态是否从 `Candidate` 进入 `Starting`；
- 确认 `SG Control Mic` 存在且未被禁用；
- 确认 `wetype_renderer` 正在运行；
- 检查微信输入法的语音快捷键是否仍是 `Ctrl+Win+Shift`；
- 检查微信输入法的“按住说话 `Ctrl+Win`”是否已经关闭；
- 在诊断页确认是否出现“麦克风载波已确认”和“已切换并确认输入法”。

### 语音图标出现，但文字没有进入目标软件

- 第二次短按后等待约3秒，让输入法完成提交；
- 确认期间不要改变焦点；
- 部分应用会让微信输入法显示“已复制”，这属于第三方输入控件兼容行为，不代表程序记录了转写内容。

### 第一次短按无法说话

这是当前遥控器硬件行为：短按只发送一次命令，不能让遥控器麦克风持续工作。使用遥控器麦克风时第一次必须长按。

### 文字乱码

当前版本通过 Unicode 键盘输入链路处理中文。请使用新版 Windows 记事本或支持 Unicode 的编辑器；如果仅某个旧软件乱码，应检查该软件的编码和输入控件。

## 设置和隐私

设置文件保存在当前用户目录：

```text
%LOCALAPPDATA%\VoiceRemoteBridge\settings.json
```

隐私边界：

- 不保存、回放或上传麦克风音频；
- 不记录语音转写文字；
- 麦克风激活探针只在内存中计算音量特征；
- 常规日志只记录设备、状态、适配器阶段和错误码；
- HID 原始报告只允许写入本地 `artifacts/` 诊断目录，不进入公开仓库。

## 从源代码构建

要求：Windows 11 x64、.NET 10 SDK。

```powershell
dotnet restore .\VoiceRemoteBridge.slnx
dotnet format .\VoiceRemoteBridge.slnx --verify-no-changes
dotnet build .\VoiceRemoteBridge.slnx --configuration Release --no-restore
dotnet run --project .\tests\VoiceRemoteBridge.Core.Tests\VoiceRemoteBridge.Core.Tests.csproj --configuration Release --no-build
dotnet run --project .\tests\VoiceRemoteBridge.Windows.Tests\VoiceRemoteBridge.Windows.Tests.csproj --configuration Release --no-build
```

生成自包含发布包：

```powershell
dotnet publish .\src\VoiceRemoteBridge.App\VoiceRemoteBridge.App.csproj --configuration Release --runtime win-x64 --self-contained true
```

项目不依赖第三方 NuGet 包。
